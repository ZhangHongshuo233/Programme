# 📜 绝学秘籍：无向图的终极阵法 —— 邻接多重表 (Adjacency Multilist)

## 一、 破局之道：为何需要多重表？

在无向图的传统**邻接表**中，一条物理边（如 A 和 B 结盟）会被强制拆分成两个独立的节点，分别存放在 A 和 B 的单链表中。

* **致命痛点**：
    1.  **状态同步极难**：如果要删除边 (A, B) 或标记该边已被访问，必须分别遍历 A 和 B 的链表去寻找对应节点，操作繁琐且极易出现数据不一致（Bug）。
    2.  **操作非原子性**：删除一条边的时间复杂度较高，属于“牵一发而动全身”。

**邻接多重表**正是为了解决无向图的这一痛点而生。它的核心哲学是：**把“关系（边）”具象化为一个唯一的物理实体（契约）。**

---

## 二、 核心心法：“一仆二主”的实体契约

在多重表中，顶点（大侠）和边（契约）是彻底分离的两种结构。一条边在内存中只有一个实例，同时被两个顶点所共享。

### 数据结构定义 (C语言)

```c
// 边节点：一份结盟契约
typedef struct EdgeNode {
    int mark;               // 状态标记：0为未处理，1为已处理/已删除
    int ivex;               // 甲方 (顶点 1)
    int jvex;               // 乙方 (顶点 2)
    struct EdgeNode* ilink; // 甲方的下一份契约 (属于 ivex 的专线)
    struct EdgeNode* jlink; // 乙方的下一份契约 (属于 jvex 的专线)
} EdgeNode;

// 顶点节点：大侠本人
typedef struct VertexNode {
    int data;               // 顶点数据 (战力、名字等)
    EdgeNode* firstedge;    // 大侠手里捏着的第一份契约
} VertexNode;
```

**心法要诀**：修改一条边的状态（如 `mark = 1`），两个顶点能**瞬间同时**感知到，实现了极致的原子操作。

## 三、 凌波微步：主观视角的寻路逻辑

多重表中最容易让人走火入魔的地方在于：**边节点没有纯粹的 `next` 指针。**
寻找下一条边时，必须基于**“主观视角”**进行判断：你现在是代表哪个大侠在查阅契约？

### 顺藤摸瓜的代码范式

```c
// 假设我们当前正在遍历大侠 i 的所有边，curr 是当前边
EdgeNode* nextEdge;

// 寻路判断：看自己匹配了契约上的哪一方
if (curr->ivex == i) {
    nextEdge = curr->ilink;  // 我是甲方，走甲方的专线
} else {
    nextEdge = curr->jlink;  // 我是乙方，走乙方的专线
}

curr = nextEdge; // 继续遍历
```

**心法要诀**：路不在脚下，路在你的身份里。匹配 `ivex` 走 `ilink`，匹配 `jvex` 走 `jlink`。

## 四、 毁尸灭迹：客观规则的内存释放

在销毁整个图时，多重表极易触发 **Use-After-Free（释放后使用）** 漏洞，因为一个边节点会被两个顶点在各自的循环中遇到两次。如果被释放两次，程序直接崩溃。

### 绝对安全的“收尸”法则

必须抛弃“主观视角”，采用一条全世界通用的“客观规则”：**只有编号较小的顶点，才有资格释放这块内存。**

```c
// 假设当前正在遍历顶点 i 的链表
int min_vex = (curr->ivex < curr->jvex) ? curr->ivex : curr->jvex;

if (min_vex == i) {
    free(curr); // 我是较小的一方，由我负责手起刀落销毁内存
}
// 如果 min_vex != i，说明我编号大，假装没看见，直接跳过（别人会/已经替我 free 了）
```

**心法要诀**：寻路靠主观身份，销毁靠客观军规。两者结合，方能进退自如，内存滴水不漏。
