# 网络流算法模块 (Network Flow Algorithms)

本模块包含了图论中最核心且应用极广的**网络流问题 (Network Flow Problems)** 的经典算法实现。网络流模型常用于解决资源分配、交通调度、物流运输以及二分图匹配等复杂的全局最优化问题。

## 📌 核心概念

在网络流问题中，图被抽象为一个流网络（如水管网络）：
1. **源点 (Source, s)**：无限提供流量的起点。
2. **汇点 (Sink, t)**：无限接收流量的终点。
3. **容量 (Capacity)**：每条边（水管）都有一个最大允许通过的流量限制。
4. **残量图 (Residual Graph) 与反向边**：网络流算法的灵魂。在正向压入流量的同时，必须建立等量的**反向容量**。这相当于一种**“反悔/撤销 (Undo)”机制**，使得算法可以自动纠正早期的贪心错误，最终收敛到全局最大流。

## 📂 算法文件导航与复杂度分析

本模块按照计算机科学对网络流算法的优化演进历史，实现了以下四个核心文件：

### 1. `ford_fulkerson_naive.c` (基础探索版)
* **算法思想**：使用最简单的 **DFS (深度优先搜索)** 在残量图中寻找增广路径。
* **特点**：代码极简，适合作为教学演示理解“反向边”的作用。
* **致命弱点**：如果遇到特殊构造的“杀手图”（如中间只有极小容量的连接），DFS 会陷入疯狂的来回撤销（拉锯战）。
* **时间复杂度**：$O(f \cdot |E|)$，其中 $f$ 为最大流。极度不稳定。

### 2. `edmonds_karp.c` (工业标准版)
* **算法思想**：Ford-Fulkerson 的究极改良版。将 DFS 替换为 **BFS (广度优先搜索)**，强制每次寻找**经过边数最少**的增广路径。
* **特点**：完美避开了拉锯战陷阱，是目前解决一般网络流问题**最标准、最通用的底层算法**。
* **时间复杂度**：$O(|V| \cdot |E|^2)$。极其稳定，完全脱离了最大流量大小的影响。

### 3. `max_capacity_path.c` (最大容量增广法)
* **算法思想**：贪心奇招。修改了 Dijkstra 算法，使其不寻找最短距离，而是寻找**瓶颈容量最大**的增广路径。
* **特点**：每次都挑“最粗的管子”灌水。在边数较少但容量极大的稀疏图中，它能以极少的循环次数迅速榨干网络。
* **时间复杂度**：$O(|E|^2 \log |V|)$ （基于不同优先队列实现略有差异）。

### 4. `min_cost_max_flow.c` (MCMF - 最小费用最大流)
* **算法思想**：商业调度终极 Boss。网络不仅有容量限制，每条边还有**单位流量成本 (Cost)**。
* **核心机制**：将寻找增广路径的机制替换为 **SPFA (最短路径算法)**。因为建立反向边意味着“退回流量”，其成本会变成**负数**，必须使用支持负权边的 SPFA 来寻找当前最便宜的路径。
* **应用**：在保证流量最大的前提下，花最少的钱。

## 🚀 编译与运行 (基于 CMake)

本项目已全面接入 CMake 构建系统。无需手动使用 GCC 链接繁杂的文件，只需在根目录操作即可：

1. 打开 VS Code，确保底部 CMake 状态栏已 Configure 完成。
2. 在目标选择器中选择你想测试的算法：
   - `[test_ff_naive]`
   - `[test_ek]`
   - `[test_max_cap]`
   - `[test_mcmf]`
3. 点击 **Run** (▶) 即可在终端查看算法的逐步压榨过程及最终结果。
